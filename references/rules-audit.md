# Анализ источников правил

## A) «Фото авито правила.txt»

Источник — сборник: заметки пользователя + статьи (gdefoto, LiteLab) + фрагменты блога/правил Авито.

### Принято

| Правило | Почему ок |
|---------|-----------|
| Генерация **4:3**, целевой размер **1920×1440** | Бриф + горизонтальный кадр |
| Safe-zone **~1300×1300** | Превью 1:1 обрезает края |
| JPG/PNG, ≤25 МБ, практика 0.3–2 МБ | Правила Авито |
| До **10** фото | Базовый лимит |
| Мебель в интерьере; товар главный | Блог Авито |
| Первое фото = обложка | CTR |
| Запрет контактов, стоков, чужих лого, рамок | Официальные требования |
| Текст на обложке ≤ ~10%, не перекрывает товар | Блог Авито |
| Без «срочно / акция / скидка» на фото | Официальный список |

### Отклонено

| Утверждение | Вердикт |
|-------------|---------|
| «На фото нельзя никакой текст» | Слишком жёстко |
| «Всегда 1280×1280» | Не мастер-формат пайплайна |
| «До 40 фото» | Не норма |
| Watermark «для защиты» | Риск |
| Цветные рамки / коллажи ок | Запрещены как приём внимания |

## B) «Еще правила.txt»

Гайд под CTR/услуги с отсылками к Habr/гайдам. Много верного про доверие и композицию; часть цифр завышена под «услуги/баннер».

### Принято (добавлено в скилл)

| Правило | Заметка |
|---------|---------|
| Первое фото: результат/объект, не прайс/визитка/коллаж/простыня текста | Усиливает обложку |
| Свои фото; не сток/Google/конкуренты | Уже было |
| Резкость, свет, без шума/пересвета | В генерацию и обработку |
| 1280×960 / **1920×1440**, **4:3** | Совпадает |
| Цвета натуральные; без кислоты/HDR-кринжа | В промпты |
| Свет: дневной / рассеянный; без вспышки в упор | В промпты/съёмку |
| Объект **60–80%** кадра | Было ~70–80% — расширили |
| Фон: интерьер/чистый; без хлама | Для мебели |
| Текст: короткий; не половина кадра | Согласовано: блок **10–25%**, не простыня |
| Кегль для 1920: читаемость на мобиле | Усилено: хук **≥72 px**, выгода **≥44 px** |
| Safe-zone / центр кадра | Усилено: **весь** текстовый блок в **1300×1300** |
| Контакты/QR/мессенджеры на фото — нет | Уже было |
| Большие watermark — нет | Уже без watermark |
| Уникальность кадров между объявлениями | Anti-dupe lead |
| Бан-лозунги: «ЛУЧШИЕ», «№1», «100%», «Гарантия результата» + акция/скидка | Расширенный бан-лист |
| Галерея: общий → детали → фактура; масштаб | Последовательность для товарки |
| Лёгкая ЦК; без жёстких фильтров | Обработка |
| CTR: светло, один объект, мало текста, «не баннер» | Чеклист обложки |

### Отклонено / скорректировано

| Утверждение | Вердикт |
|-------------|---------|
| «Оптимально 10–20 / товары 10–25 фото» | **Нет.** Дефолт — **до 10** |
| «Коллаж 2–4 фото ок» | На **обложке — нет.** Отдельные кадры в галерее |
| «Логотип 5–8% желателен» | Для товарки мебели **не обязателен**; если есть — ≤5–8%, не центр |
| Формула услуг: **20–25% кадра = заголовок** | **Скорректировано:** оверлей **10–25%** целиком (плашка+текст) внутри 1300×1300; не полкадра текстом и не «тонкая полоска» |
| «Отзывы/сертификаты на фото» | Не на обложку; только если реально и без контактов |
| «Люди / униформа / процесс» как must | Для **услуг** ок; для **товарки** — опционально на фото 5–10 |
| Фон «без людей» vs «люди = доверие» | Обложка мебели = **товар**; люди позже и с согласием |

### Итог для пайплайна мебели

Обложка = реальный гарнитур в интерьере + минимум текста в safe-zone.  
Галерея = ракурсы, детали, масштаб.  
Не превращать первое фото в баннер услуг с 25% текста.

## C2) Архив + ImageNames (инструкция Авито, 2026)

Принято в скилл как **режим F** → [archive-upload.md](archive-upload.md). Дефолт массового фида не менять (остаётся ImageUrls).

| Правило | Заметка |
|---------|---------|
| Продумать названия/нумерацию до архива | Удобный ImageNames |
| Фото в ZIP **без папок** внутри | Не `zip -r folder/`; плоский корень |
| ImageNames = имя с расширением (`Фото_1.jpg`) | Точное совпадение с файлом в ZIP |
| Несколько имён — `\|` или перевод строки | В пайплайне предпочитать ` \| ` |
| Архив загружать **вместе** с Excel | Один пакет автозагрузки |
| Архив + Excel ≤ **100 МБ** | Крупный фид → оставаться на Диске/URL |
| Не смешивать ImageUrls и ImageNames в одной строке | Взаимоисключение способов |
