# Загрузка фото архивом (ImageNames + ZIP)

Альтернатива Яндекс.Диску / ImageUrls. Источник: официальная инструкция Авито по автозагрузке («Подготовьте фотографии» → архив).

**Дефолт пайплайна** — всё ещё **ImageUrls** (режим A/C/D). Режим **F (архив)** — только по явному запросу брифа или когда Диск не подключён / малый фид без cloud-api.

## Взаимоисключение с URL

| Способ | ImageUrls | ImageNames | Файлы |
|--------|-----------|------------|--------|
| Яндекс.Диск / HTTP | `url1 \| url2 \| …` | **пусто** | на Диске / по URL |
| Архив | **пусто** | `file1.jpg \| file2.jpg \| …` | ZIP рядом с Excel |

Не смешивать в одной строке ImageUrls и ImageNames. Не писать path папок в ImageNames — только **имя файла с расширением**.

## Правила Авито (дословно по смыслу)

1. **Подготовить фотографии.** Сразу продумать **названия или нумерацию**, чтобы удобно перечислять их в файле.
2. Выделить фото и **добавить в архив**:
   - **не** добавлять фото «в папку внутри архива»;
   - **не** разделять по папкам внутри архива;
   - все JPG/PNG — **в корне ZIP** (плоский список файлов).
3. В Excel в параметре **ImageNames** / «Названия фото» указать название с расширением, например `Фото_1.jpg`.
4. Несколько фото — между именами знак **`|`** или **перенос строки**. В этом скилле для единообразия с ImageUrls предпочитать **` | `** (пробел-пайп-пробел).
5. **Загрузить архив вместе с Excel-файлом** в автозагрузку.
6. **Общий размер архива + Excel ≤ 100 МБ.**

Инструкцию по созданию ZIP смотреть на сайте ОС пользователя — агент не обязан учить zip-утилиту, но должен выдать плоский архив без вложенных папок.

## Именование файлов (практика скилла)

Чтобы имена были уникальны между объявлениями и удобны в Excel:

```text
{Id}-01.jpg
{Id}-02.jpg
{Id}-03.jpg
{Id}-04.jpg
```

или ASCII без кириллицы (если бриф просит):

```text
ad-{Id}-01.jpg | ad-{Id}-02.jpg | …
```

- Расширение обязательно (`.jpg` / `.png`), регистр как в архиве.
- Имя в ImageNames = **точное** имя файла в корне ZIP (байт-в-байт).
- Первое имя = lead/обложка; у разных строк — **разные** первые файлы (как unique firsts при URL).
- До **10** фото на объявление.

Пример ячейки:

```text
k2-1000-01.jpg | k2-1000-02.jpg | k2-1000-03.jpg | k2-1000-04.jpg
```

## Сборка архива

```
Task Progress:
- [ ] Кадры 4:3, цель 1920×1440 (техстандарт скилла)
- [ ] Плоский staging: все JPG в одной папке-без-подпапок
- [ ] ZIP из содержимого staging (не из родительской папки с вложенностью)
- [ ] ImageNames заполнены; ImageUrls пусто
- [ ] unique firsts ≈ числу объявлений
- [ ] sizeof(zip) + sizeof(xlsx) ≤ 100 МБ
- [ ] Активные строки: фото/имена не менять без override
```

### Как не сломать ZIP

| Делать | Не делать |
|--------|-----------|
| `cd staging && zip ../photos.zip *.jpg` | `zip -r photos.zip photos/` (появится папка `photos/` внутри) |
| Один уровень файлов в корне архива | `sets/`, `heroes/`, вложенные каталоги в ZIP |
| Сжимать уже готовые JPG | Дублировать одни и те же тяжёлые heroes без нужды |

Если локально кадры лежат в `sets/` + `heroes/` (пайплайн C) — для архива **скопировать/переименовать** нужные файлы в плоский staging, не класть дерево папок в ZIP.

## Лимит 100 МБ

- Цель на кадр: **0.3–2 МБ** (как в техстандарте).
- Большой фид (сотни heroes) часто **не влезает** в 100 МБ вместе с xlsx → оставаться на **ImageUrls + Яндекс.Диск**.
- Перед сдачей: проверить `du -sb archive.zip feed.xlsx` (сумма ≤ 104857600 байт).

## Когда выбирать F

| Ситуация | Способ |
|----------|--------|
| Массовый фид, Диск подключён | A / C / D (URL) |
| Малый пакет, Диск нет / пользователь просит ZIP | **F** |
| Премиум E → production | по брифу: URL (дефолт) или F |

## Отчёт режима F

Путь ZIP + xlsx, число файлов в корне архива, сумма МБ, N строк с ImageNames, unique firsts, ImageUrls пусто.
